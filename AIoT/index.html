      02. 網路通訊架構與網通特殊需求

      Matter 採用完全透明的 IPv6 端到端傳輸，不需傳統專有閘道進行協定轉換。了解 Thread Mesh、Wi-Fi 高頻寬與 mDNS 多播 (Multicast) 的網通關鍵考量。

      📊 Thread vs Zigbee 併發傳輸延遲比較

      單位：毫秒 (ms) / 多躍點 Multi-hop

      學術研究顯示：Zigbee 在小規模單一點對點具備微幅優勢，但 Matter over Thread 在大規模節點併發（如同時發動全屋 30 盞燈調光）時，憑藉去中心化 IPv6 路由展現出次秒級（Sub-second）且極穩定的延遲表現。

      🛠️ 路由器與網通架構檢核清單

      實務中高達 80% 配網失敗或「無法連線」問題起源於家庭網路層對 IPv6 多播 (Multicast) 的攔截。

      1. IPv6 Multicast & mDNS / DNS-SD Port 5540

      必須開啟路由器 IPv6 前綴下發，並關閉過度嚴格的 IGMP/MLD Snooping。若是劃分 VLAN 的 Prosumer 環境，需配置 mDNS Reflector (如 Avahi)。

      2. Thread 邊界路由器 (TBR) 整合 Layer 3 IPv6 Bridge

      TBR（如 Apple HomePod 或 Google Nest Hub）僅進行網路層封包路由，無須應用層轉碼。Matter 1.4+ 規範了 HRAP 路由器整合標準。

      3. 藍牙 (Bluetooth LE) 角色定位 僅用於 Commissioning

      BLE 僅在出廠配網階段發揮作用（PASE 握手）。一旦成功加入 Wi-Fi 或 Thread 網路，BLE 無線電即自動關閉。

      03. 邊緣硬體需求與動態估算器

      Matter 龐大的 IPv6 協定堆疊與加密憑證，對邊緣 MCU 的 Flash ROM 與 SRAM 提出了極高考驗。傳統 128KB 級別 MCU 已無法承受商業化需求。

      05. 智慧平台整合與舊設備橋接技術

      如何在 Apple Home、Google Home 與 Home Assistant 之間無縫共存？了解增強型配網視窗 (ECW) 與 Zigbee / Z-Wave 的 Unify SDK 橋接機制。

      🔗 ECW (增強型配網視窗) 跨平台分享流程

      當設備已加入 Apple Home 後，欲將其分享至 Home Assistant 時，無需重新觸碰實體條碼，流程如下：

      步驟 1: 開啟 ECW 視窗

      原控制器發送 `Administrator Commissioning Cluster` 指令，開啟 180 秒動態 PIN 碼與臨時 PASE 視窗。

      步驟 2: 第二平台掃描與 PASE

      Home Assistant 透過 IPv6 mDNS 發現設備，輸入該動態 PIN 碼直接經由 IP 網路建立 PASE 連線。

      步驟 3: 頒發第二張 NOC 憑證

      設備取得 Home Assistant 的 Fabric NOC，完成 Multi-Admin 設定，兩平台即時同步同一真相源。

      🌉 舊有 Zigbee / Z-Wave 橋接器資料對映 (Data Mapping)

      Matter Bridge 在網路上呈現為單一 Node，並將下方接掛的 Zigbee 設備暴露為不同的 Endpoint。

      Unify SDK 轉換展示 (Zigbee -> Matter Endpoint)
      Matter Bridge (Node ID: 0x99A)
      ├─ Endpoint 0: Bridge Utility & Control
      ├─ Endpoint 1: Bridged Device (Zigbee 溫濕度計)
      └─ Cluster: Temperature Measurement (0x0402)
      └─ Endpoint 2: Bridged Device (Z-Wave 門窗感測器)
      └─ Cluster: Boolean State (0x0045)
      💡 當 Apple Home 發送 `Read Attribute` 給 Endpoint 1 時，橋接器會在毫秒內翻譯為 Zigbee ZCL 指令並傳回數據。
